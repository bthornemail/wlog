In [mathematics](https://en.wikipedia.org/wiki/Mathematics "Mathematics") and [combinatorics](https://en.wikipedia.org/wiki/Combinatorics "Combinatorics"), a **centered hexagonal number**, or **centered** **hexagon number**,[[1]](https://en.wikipedia.org/wiki/Centered_hexagonal_number#cite_note-1)[[2]](https://en.wikipedia.org/wiki/Centered_hexagonal_number#cite_note-Deza-2) is a [centered](https://en.wikipedia.org/wiki/Centered_polygonal_number "Centered polygonal number") [figurate number](https://en.wikipedia.org/wiki/Figurate_number "Figurate number") that represents a [hexagon](https://en.wikipedia.org/wiki/Hexagon "Hexagon") with a dot in the center and all other dots surrounding the center dot in a [hexagonal lattice](https://en.wikipedia.org/wiki/Hexagonal_lattice "Hexagonal lattice"). ## Formula

[![](https://upload.wikimedia.org/wikipedia/commons/thumb/7/7e/Centered_hexagonal_%3D_1_%2B_6triangular.svg/250px-Centered_hexagonal_%3D_1_%2B_6triangular.svg.png)](https://en.wikipedia.org/wiki/File:Centered_hexagonal_%3D_1_%2B_6triangular.svg)

Dissection of hexagonal number into six triangles with a remainder of one. The triangles can be re-assembled pairwise to give three [parallelograms](https://en.wikipedia.org/wiki/Parallelogram "Parallelogram") of _n_(_n_−1) dots each.

The nth centered hexagonal number is given by the formula[[2]](https://en.wikipedia.org/wiki/Centered_hexagonal_number#cite_note-Deza-2)

H(n)=n3−(n−1)3=3n(n−1)+1=3n2−3n+1.![{\displaystyle H(n)=n^{3}-(n-1)^{3}=3n(n-1)+1=3n^{2}-3n+1.\,}](https://wikimedia.org/api/rest_v1/media/math/render/svg/57ab960df54ff06afe4d7eb24757758f416151e5)

Expressing the formula as

H(n)=1+6(n(n−1)2)![{\displaystyle H(n)=1+6\left({\frac {n(n-1)}{2}}\right)}](https://wikimedia.org/api/rest_v1/media/math/render/svg/7b7906504b2c0e8d574dd70018738c85e738ed3c)

shows that the centered hexagonal number for n is 1 more than 6 times the (_n_ − 1)th [triangular number](https://en.wikipedia.org/wiki/Triangular_number "Triangular number").

In the opposite direction, the _index_ n corresponding to the centered hexagonal number H=H(n)![{\displaystyle H=H(n)}](https://wikimedia.org/api/rest_v1/media/math/render/svg/37b55116df2a28b1028b2ca5dbe88ad4c0beabb4) can be calculated using the formula

n=3+12H−36.![{\displaystyle n={\frac {3+{\sqrt {12H-3}}}{6}}.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/03d0b93fe17b0d54371bc6a4043add7d8b334946)

This can be used as a test for whether a number H is centered hexagonal: it will be if and only if the above expression is an integer.

## Recurrence and generating function

The centered hexagonal numbers H(n)![{\displaystyle H(n)}](https://wikimedia.org/api/rest_v1/media/math/render/svg/be4e983a8ea1e65323a9af036edd5d57c51e8c18) satisfy the [recurrence relation](https://en.wikipedia.org/wiki/Recurrence_relation "Recurrence relation")[[2]](https://en.wikipedia.org/wiki/Centered_hexagonal_number#cite_note-Deza-2)

H(n+1)=H(n)+6n.![{\displaystyle H(n+1)=H(n)+6n.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/b06bf50fe6576387ae1395bf2d17653040d7be2f)

From this we can calculate the [generating function](https://en.wikipedia.org/wiki/Generating_function "Generating function") F(x)=∑n≥0H(n)xn![{\displaystyle F(x)=\sum _{n\geq 0}H(n)x^{n}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/f235bfdad7b8759cc958a589b0b492a3a89a983f). The generating function satisfies

F(x)=x+xF(x)+∑n≥26nxn.![{\displaystyle F(x)=x+xF(x)+\sum _{n\geq 2}6nx^{n}.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/6c6256506f544c90c93c7fd7f5789edcff6c6162)

The latter term is the [Taylor series](https://en.wikipedia.org/wiki/Taylor_series "Taylor series") of 6x(1−x)2−6x![{\displaystyle {\frac {6x}{(1-x)^{2}}}-6x}](https://wikimedia.org/api/rest_v1/media/math/render/svg/4fdc2a179c10af2150750f84c767bd785bb39eb3), so we get

(1−x)F(x)=x+6x(1−x)2−6x=x+4x2+x3(1−x)2![{\displaystyle (1-x)F(x)=x+{\frac {6x}{(1-x)^{2}}}-6x={\frac {x+4x^{2}+x^{3}}{(1-x)^{2}}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/0c80bc0443f1c4f8b1f2b447a3d0628297494f1b)

and end up at

F(x)=x+4x2+x3(1−x)3.![{\displaystyle F(x)={\frac {x+4x^{2}+x^{3}}{(1-x)^{3}}}.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/ee6c44cf0439bd4d9bdef96516513c467dfba09a)

## Properties

[![](https://upload.wikimedia.org/wikipedia/commons/thumb/a/a0/Visual_proof_centered_hexagonal_numbers_sum.svg/250px-Visual_proof_centered_hexagonal_numbers_sum.svg.png)](https://en.wikipedia.org/wiki/File:Visual_proof_centered_hexagonal_numbers_sum.svg)

[Proof without words](https://en.wikipedia.org/wiki/Proof_without_words "Proof without words") of the sum of the first _n_ hex numbers by arranging _n_3 semitransparent balls in a cube and viewing along a [space diagonal](https://en.wikipedia.org/wiki/Space_diagonal "Space diagonal") – colour denotes cube layer and line style denotes hex number

In [base 10](https://en.wikipedia.org/wiki/Base_10 "Base 10") one can notice that the hexagonal numbers' rightmost (least significant) digits follow the pattern 1–7–9–7–1 (repeating with [period](https://en.wikipedia.org/wiki/Periodic_sequence "Periodic sequence") 5). This follows from the [last digit of the triangle numbers](https://en.wikipedia.org/wiki/Triangular_number#Other_properties "Triangular number") (sequence [A008954](https://oeis.org/A008954 "oeis:A008954") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")) which repeat 0-1-3-1-0 when taken modulo 5. In [base 6](https://en.wikipedia.org/wiki/Base_6 "Base 6") the rightmost digit is always 1: 16, 116, 316, 1016, 1416, 2316, 3316, 4416... This follows from the fact that every centered hexagonal number modulo 6 (=106) equals 1.

The sum of the first n centered hexagonal numbers is [_n_3](https://en.wikipedia.org/wiki/Cube_\(algebra\) "Cube (algebra)"). That is, centered hexagonal [pyramidal numbers](https://en.wikipedia.org/wiki/Pyramidal_number "Pyramidal number") and [cubes](https://en.wikipedia.org/wiki/Cubic_number "Cubic number") are the same numbers, but they represent different shapes. Viewed from the opposite perspective, centered hexagonal numbers are differences of two consecutive cubes, so that the centered hexagonal numbers are the [gnomon](https://en.wikipedia.org/wiki/Figurate_number#Gnomon "Figurate number") of the cubes. (This can be seen geometrically from the diagram.) In particular, [prime](https://en.wikipedia.org/wiki/Prime_number "Prime number") centered hexagonal numbers are [cuban primes](https://en.wikipedia.org/wiki/Cuban_prime "Cuban prime").

The difference between (2_n_)2 and the nth centered hexagonal number is a number of the form 3_n_2 + 3_n_ − 1, while the difference between (2_n_ − 1)2 and the nth centered hexagonal number is a [pronic number](https://en.wikipedia.org/wiki/Pronic_number "Pronic number").

A **magic hexagon** of order _n_ is an arrangement of numbers in a [centered hexagonal pattern](https://en.wikipedia.org/wiki/Centered_hexagonal_number "Centered hexagonal number") with _n_ cells on each edge, in such a way that the numbers in each row, in all three directions, sum to the same [magic constant](https://en.wikipedia.org/wiki/Magic_constant "Magic constant") _M_. A **normal magic hexagon** contains the consecutive [integers](https://en.wikipedia.org/wiki/Integer "Integer") from 1 to 3_n_2 − 3_n_ + 1. Normal magic hexagons exist only for _n_ = 1 (which is trivial, as it is composed of only 1 cell) and _n_ = 3. Moreover, the solution of order 3 is unique up to reflections and rotations.[[1]](https://en.wikipedia.org/wiki/Magic_hexagon#cite_note-1) Meng gives a less intricate constructive [proof](https://en.wikipedia.org/wiki/Mathematical_proof "Mathematical proof").[[2]](https://en.wikipedia.org/wiki/Magic_hexagon#cite_note-2)

The order-3 magic hexagon with numbers 1 through 19 and magic sum 38 has been published many times as a 'new' discovery. An early reference, and possibly the first discoverer, is [Ernst von Haselberg](https://en.wikipedia.org/w/index.php?title=Ernst_von_Haselberg&action=edit&redlink=1 "Ernst von Haselberg (page does not exist)") (1887)[_[citation needed](https://en.wikipedia.org/wiki/Wikipedia:Citation_needed "Wikipedia:Citation needed")_].

## Proof of normal magic hexagons

The numbers in the hexagon are consecutive, and run from 1 to 3n2−3n+1![{\displaystyle 3n^{2}-3n+1}](https://wikimedia.org/api/rest_v1/media/math/render/svg/432d1a63960522063869b964ae347a0ca9f07172). Hence their sum is a [triangular number](https://en.wikipedia.org/wiki/Triangular_number "Triangular number"), namely

s=12(3n2−3n+1)(3n2−3n+2)=9n4−18n3+18n2−9n+22![{\displaystyle s={1 \over {2}}(3n^{2}-3n+1)(3n^{2}-3n+2)={9n^{4}-18n^{3}+18n^{2}-9n+2 \over {2}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/215a33b789e00cac837631b0d28e37d37787ab2f)

There are _r_ = 2_n_ − 1 rows running along any given direction (E-W, NE-SW, or NW-SE). Each of these rows sums up to the same number _M_. Therefore:

M=sr=9n4−18n3+18n2−9n+22(2n−1)![{\displaystyle M={s \over {r}}={9n^{4}-18n^{3}+18n^{2}-9n+2 \over {2(2n-1)}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/32a2f599ad2237d683d6e07b92c7f45cde423c2e)

This can be rewritten as

M=(9n34−27n28+45n16−2732)+532(2n−1)![{\displaystyle M=\left({\frac {9n^{3}}{4}}-{\frac {27n^{2}}{8}}+{\frac {45n}{16}}-{\frac {27}{32}}\right)+{\frac {5}{32\left(2n-1\right)}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/81826719faa73b55a302645385f0d846a3594ae5)

Multiplying throughout by 32 gives

32M=72n3−108n2+90n−27+52n−1![{\displaystyle 32M=72n^{3}-108n^{2}+90n-27+{5 \over 2n-1}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/82229d69e051d25800e4fca1f7db078898664374)

which shows that 52n−1![{\displaystyle {\frac {5}{2n-1}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/ff687ec96a584e2ea2be835d2dd014bc2c12e582) must be an integer, hence 2_n_ − 1 must be a factor of 5, namely 2_n_ − 1 = ±1 or 2_n_ − 1 = ±5. The only n≥1![{\displaystyle n\geq 1}](https://wikimedia.org/api/rest_v1/media/math/render/svg/d8ce9ce38d06f6bf5a3fe063118c09c2b6202bfe) that meet this condition are n=1![{\displaystyle n=1}](https://wikimedia.org/api/rest_v1/media/math/render/svg/d9ec7e1edc2e6d98f5aec2a39ae5f1c99d1e1425) and n=3![{\displaystyle n=3}](https://wikimedia.org/api/rest_v1/media/math/render/svg/1c5a5a42ced00df920fad4ab2d4acdb960a4105b), proving that there are no normal magic hexagons except those of order 1 and 3.

## Magic T-hexagons

Hexagons can also be constructed with triangles, as the following diagrams show.

|   |   |
|---|---|
|[![](https://upload.wikimedia.org/wikipedia/commons/thumb/9/95/MagicTHexagon-Order2-blank.svg/250px-MagicTHexagon-Order2-blank.svg.png)](https://en.wikipedia.org/wiki/File:MagicTHexagon-Order2-blank.svg)|[![](https://upload.wikimedia.org/wikipedia/commons/thumb/5/5b/MagicTHexagon-Order2.svg/250px-MagicTHexagon-Order2.svg.png)](https://en.wikipedia.org/wiki/File:MagicTHexagon-Order2.svg)|
|Order 2|Order 2 with numbers 1–24|

This type of configuration can be called a T-hexagon and it has many more properties than the hexagon of hexagons.

As with the above, the rows of triangles run in three directions and there are 24 triangles in a T-hexagon of order 2. In general, a T-hexagon of order _n_ has 6n2![{\displaystyle 6n^{2}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/74057f6a7e4bdebef3c6f57a61b359e5b6d4d252) triangles. The sum of all these numbers is given by:

S=3n2(6n2+1)![{\displaystyle S=3n^{2}(6n^{2}+1)}](https://wikimedia.org/api/rest_v1/media/math/render/svg/63708f1ca7fb2359876401d6d3d984f58402dd43)

If we try to construct a magic T-hexagon of side _n_, we have to choose _n_ to be [even](https://en.wikipedia.org/wiki/Parity_\(mathematics\) "Parity (mathematics)"), because there are _r_ = 2_n_ rows so the sum in each row must be

M=SR=3n2(6n2+1)2n![{\displaystyle M={\frac {S}{R}}={\frac {3n^{2}(6n^{2}+1)}{2n}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/d7ffbac96611eef1db88c579ba89ca4d826ffd2d)

For this to be an integer, _n_ has to be even. To date, magic T-hexagons of order 2, 4, 6 and 8 have been discovered. The first was a magic T-hexagon of order 2, discovered by John Baker on 13 September 2003. Since that time, John has been collaborating with David King, who discovered that there are 59,674,527 non-congruent magic T-hexagons of order 2.

Magic T-hexagons have a number of properties in common with magic squares, but they also have their own special features. The most surprising of these is that the sum of the numbers in the triangles that point upwards is the same as the sum of those in triangles that point downwards (no matter how large the T-hexagon). In the above example,

17 + 20 + 22 + 21 + 2 + 6 + 10 + 14 + 3 + 16 + 12 + 7

= 5 + 11 + 19 + 9 + 8 + 13 + 4 + 1 + 24 + 15 + 23 + 18

= 150

A **prime reciprocal magic square** is a [magic square](https://en.wikipedia.org/wiki/Magic_square "Magic square") using the decimal digits of the [reciprocal](https://en.wikipedia.org/wiki/Reciprocal_\(mathematics\) "Reciprocal (mathematics)") of a [prime number](https://en.wikipedia.org/wiki/Prime_number "Prime number").

## Introduction

Consider a unit fraction, like 1/3 or 1/7. In base ten, the remainder, and so the digits, of 1/3 repeats at once: 0.3333.... However, the remainders of 1/7 repeat over six, or 7−1, digits: 1/7 = 0·142857142857142857... If you examine the multiples of 1/7, you can see that each is a [cyclic permutation](https://en.wikipedia.org/wiki/Cyclic_permutation "Cyclic permutation") of these six digits:1/7=0.142857…2/7=0.285714…3/7=0.428571…4/7=0.571428…5/7=0.714285…6/7=0.857142…![{\displaystyle {\begin{aligned}1/7&=0.142857\dots \\2/7&=0.285714\dots \\3/7&=0.428571\dots \\4/7&=0.571428\dots \\5/7&=0.714285\dots \\6/7&=0.857142\dots \end{aligned}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/e6a133dbfa02bdf913c35ebe1715cfadf686f80e)

If the digits are laid out as a [square](https://en.wikipedia.org/wiki/Square "Square"), each row and column sums to 1 + 4 + 2 + 8 + 5 + 7 = 27. This yields the smallest base-10 non-normal, prime reciprocal [magic square](https://en.wikipedia.org/wiki/Magic_square "Magic square")

|   |   |   |   |   |   |
|---|---|---|---|---|---|
|1|4|2|8|5|7|
|2|8|5|7|1|4|
|4|2|8|5|7|1|
|5|7|1|4|2|8|
|7|1|4|2|8|5|
|8|5|7|1|4|2|

In contrast with its rows and columns, the _diagonals_ of this square do not sum to 27; however, their [mean](https://en.wikipedia.org/wiki/Arithmetic_mean "Arithmetic mean") is 27, as one diagonal adds to 23 while the other adds to 31.

All prime reciprocals in any [base](https://en.wikipedia.org/wiki/Radix "Radix") with a p−1![{\displaystyle p-1}](https://wikimedia.org/api/rest_v1/media/math/render/svg/f356ae51988add41a7da343e6b6d48fa968da162) period will generate magic squares where all rows and columns produce a [magic constant](https://en.wikipedia.org/wiki/Magic_constant "Magic constant"), and only a select few will be **full**, such that their diagonals, rows and columns collectively yield equal sums.

## Decimal expansions

In a full, or otherwise prime reciprocal magic square with p−1![{\displaystyle p-1}](https://wikimedia.org/api/rest_v1/media/math/render/svg/f356ae51988add41a7da343e6b6d48fa968da162) period, the even number of k−th rows in the square are arranged by multiples of 1/p![{\displaystyle 1/p}](https://wikimedia.org/api/rest_v1/media/math/render/svg/2cdfd6eb8d2c6f424b698d06aa99d31895c47e91) — not necessarily successively — where a magic constant can be obtained.

For instance, an [even](https://en.wikipedia.org/wiki/Parity_\(mathematics\) "Parity (mathematics)") repeating [cycle](https://en.wikipedia.org/wiki/Cyclic_number "Cyclic number") from an odd, prime reciprocal of p that is divided into n−digit strings creates pairs of [complementary sequences](https://en.wikipedia.org/wiki/Method_of_complements#Numeric_complements "Method of complements") of digits that yield strings of nines (9) when added together:

1/7= 0.142857…+ 0.857142…=6/7−−−−−−−−−−−− 0.999999…1/13= 0.076923076923…+ 0.923076923076…=12/13−−−−−−−−−−−− 0.999999999999…1/19= 0.052631578947368421…+ 0.947368421052631578…=18/19−−−−−−−−−−−− 0.999999999999999999…![{\displaystyle {\begin{aligned}1/7=&{\text{ }}0.142\;857\dots \\+&{\text{ }}0.857\;142\ldots =6/7\\&------------\\&{\text{ }}0.999\;999\ldots \\\\1/13=&{\text{ }}0.076\;923\;076\;923\dots \\+&{\text{ }}0.923\;076\;923\;076\ldots =12/13\\&------------\\&{\text{ }}0.999\;999\;999\;999\ldots \\\\1/19=&{\text{ }}0.052631578\;947368421\dots \\+&{\text{ }}0.947368421\;052631578\ldots =18/19\\&------------\\&{\text{ }}0.999999999\;999999999\dots \\\end{aligned}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/fe8cf12f8176f7912ef2203de786bf08a15e3d9d)

This is a result of [Midy's theorem](https://en.wikipedia.org/wiki/Midy%27s_theorem "Midy's theorem").[[1]](https://en.wikipedia.org/wiki/Prime_reciprocal_magic_square#cite_note-1)[[2]](https://en.wikipedia.org/wiki/Prime_reciprocal_magic_square#cite_note-2) These complementary sequences are generated between multiples of [prime reciprocals](https://en.wikipedia.org/wiki/Reciprocals_of_primes "Reciprocals of primes") that add to 1.

More specifically, a factor n in the numerator of the reciprocal of a prime number p will shift the [decimal places](https://en.wikipedia.org/wiki/Decimal_place "Decimal place") of its decimal expansion accordingly,

1/23=0.0434782608695652173913…2/23=0.0869565217391304347826…4/23=0.1739130434782608695652…8/23=0.3478260869565217391304…16/23=0.6956521739130434782608…![{\displaystyle {\begin{aligned}1/23&=0.04347826\;08695652\;173913\ldots \\2/23&=0.08695652\;17391304\;347826\ldots \\4/23&=0.17391304\;34782608\;695652\ldots \\8/23&=0.34782608\;69565217\;391304\ldots \\16/23&=0.69565217\;39130434\;782608\ldots \\\end{aligned}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/f70eb65c7863a8ead37563348e134b433a02587d)

In this case, a factor of 2 moves the repeating decimal of ⁠1/23⁠ by eight places.

A uniform solution of a prime reciprocal magic square, whether full or not, will hold rows with successive multiples of 1/p![{\displaystyle 1/p}](https://wikimedia.org/api/rest_v1/media/math/render/svg/2cdfd6eb8d2c6f424b698d06aa99d31895c47e91). Other magic squares can be constructed whose rows do not represent consecutive multiples of 1/p![{\displaystyle 1/p}](https://wikimedia.org/api/rest_v1/media/math/render/svg/2cdfd6eb8d2c6f424b698d06aa99d31895c47e91), which nonetheless generate a magic sum.

## Methods of construction

Trivial examples excepted, there are no known easy methods for producing geomagic squares. To date, two approaches have been explored.[[11]](https://en.wikipedia.org/wiki/Geometric_magic_square#cite_note-11) Where the pieces to be used are _[polyforms](https://en.wikipedia.org/wiki/Polyform "Polyform")_, or shapes built up from repeated units, an exhaustive search by computer becomes possible.

In the case of Figure 1, for instance, a first step would be to decide on the piece sizes to be used (in this case all the same), and the shape of the desired target. An initial program would then be able to generate a list _L_ corresponding to every possible tiling of this target shape by 3 distinct decominoes (polyominoes of size 10). Each decomino is represented by a unique integer, so that _L_ will consist of a list of integer triads. A subsequent routine can then run through and test every combination of three different triads in turn. The test will consist in treating the candidate triads as the row entries in a 3 × 3 square, and then checking to see whether the columns and diagonals thus formed each contain 3 integers that are also in _L_—which is to say, are also target-tiling triads. If so, a 3 × 3 geomagic square using 9 decominoes and selected target has been identified. If this fails, alternative target shapes can be tried. An elaborated version of the same method can be used to search for larger squares, or for squares including differently-sized pieces.

An alternative method of construction begins with a trivial geomagic square showing repeated pieces, the shapes of which are then modified so as to render each distinct, but without disrupting the square's magic property. This is achieved by means of an algebraic template such as seen below, the distinct variables in which are then interpreted as different shapes to be either appended to or excised from the initial pieces, depending on their sign.

## Relation to traditional magic squares

Contrary to the impression made at first sight, it is a misunderstanding to regard the term 'geomagic square' as referring to some category of magic square. In fact the exact opposite is the case: every (additive) magic square is a particular instance of a geomagic square, but never vice versa. The point is made clear by the example below that appears in a wide-ranging article on geomagic squares by [Jean-Paul Delahaye](https://en.wikipedia.org/wiki/Jean-Paul_Delahaye "Jean-Paul Delahaye") in _[Pour la Science](https://fr.wikipedia.org/wiki/Pour_la_Science "fr:Pour la Science")_, the French version of _[Scientific American](https://en.wikipedia.org/wiki/Scientific_American "Scientific American")_.[[12]](https://en.wikipedia.org/wiki/Geometric_magic_square#cite_note-PourlaScience-12) In this case the target "shape" for the geomagic square at right is simply a one dimensional line segment 15 units long, the pieces again being no more than straight line segments. As such, the latter is a straightforward translation into geometrical terms of the numerical magic square at left.

The point being that every numerical magic square can be understood as a one-dimensional geomagic square as above. Or as Sallows himself puts it, "Traditional magic squares featuring numbers are then revealed as that particular case of 'geomagic' squares in which the elements are all one-dimensional."[[3]](https://en.wikipedia.org/wiki/Geometric_magic_square#cite_note-mathent-3) This however does not exhaust the 1D case, because there exist 1D geomagic squares whose components are _disconnected_ line segments, and which do not correspond to any numerical magic square. Thus, even in dimension one, the traditional types correspond to only a tiny subset of all geometric magic squares.

There was one design decision. The delta law:



rotl(x,1) XOR rotl(x,3) XOR rotr(x,2) XOR C



Four choices inside that: rotations (not shifts, so no bits are lost), XOR (reversible), a constant (breaks the zero fixed point), mask to width (keeps state bounded). 



That is the entire design.



Everything else was computed by the math:



Period = 8 → property of that specific law on 16-bit space

Prime 73 → smallest prime whose decimal repeats with period 8

Block B = [0,1,3,6,9,8,6,3] → the digits of 1/73

W = 36 → sum of B

Orbit/offset recovery → just divmod(position, 36)



Nobody chose 73. The law has period 8. The smallest prime with decimal period 8 is 73. The system found it.

The _n_th star number is given by the formula _Sn_ = 6_n_(_n_ − 1) + 1. The first 45 star numbers are 1, 13, 37, 73, 121, 181, 253, 337, 433, 541, 661, 793, 937, 1093, 1261, 1441, 1633, 1837, 2053, 2281, 2521, 2773, 3037, 3313, 3601, 3901, 4213, 4537, 4873, 5221, 5581, 5953, 6337, 6733, 7141, 7561, 7993, 8437, 8893, 9361, 9841, 10333, 10837, 11353, and 11881. (sequence [A003154](https://oeis.org/A003154 "oeis:A003154") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences"))

The [digital root](https://en.wikipedia.org/wiki/Digital_root "Digital root") of a star number is always 1 or 4, and progresses in the sequence 1, 4, 1. The last two digits of a star number in base 10 are always 01, 13, 21, 33, 37, 41, 53, 61, 73, 81, or 93.

Unique among the star numbers is 35113, since its prime factors (i.e., 13, 37 and 73) are also consecutive star numbers.

## Relationships to other kinds of numbers

[![](https://upload.wikimedia.org/wikipedia/commons/thumb/4/48/Star_number_visual_proof.svg/250px-Star_number_visual_proof.svg.png)](https://en.wikipedia.org/wiki/File:Star_number_visual_proof.svg)

[Proof without words](https://en.wikipedia.org/wiki/Proof_without_words "Proof without words") that the _n_-th star number is 12 times the (_n_−1)-th triangular number, plus one

Geometrically, the _n_th star number is made up of a central point and 12 copies of the (_n_−1)th [triangular number](https://en.wikipedia.org/wiki/Triangular_number "Triangular number") — making it numerically equal to the _n_th [centered dodecagonal number](https://en.wikipedia.org/wiki/Centered_polygonal_number "Centered polygonal number"), but differently arranged. As such, the formula the _n_th star number can be written as _Sn_ = 1 + 12_Tn−1_ where _Tn_ = ⁠_n_ (_n_ + 1)/2⁠.

Infinitely many star numbers are also [triangular numbers](https://en.wikipedia.org/wiki/Triangular_number "Triangular number"), the first four being _S_1 = 1 = _T_1, _S_7 = 253 = _T_22, _S_91 = 49141 = _T_313, and _S_1261 = 9533161 = _T_4366 (sequence [A156712](https://oeis.org/A156712 "oeis:A156712") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")).

Infinitely many star numbers are also [square numbers](https://en.wikipedia.org/wiki/Square_number "Square number"), the first four being _S_1 = 12, _S_5 = 121 = 112, _S_45 = 11881 = 1092, and _S_441 = 1164241 = 10792 (sequence [A054318](https://oeis.org/A054318 "oeis:A054318") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")), for square stars (sequence [A006061](https://oeis.org/A006061 "oeis:A006061") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")).

A **star prime** is a star number that is [prime](https://en.wikipedia.org/wiki/Prime_number "Prime number"). The first few star primes (sequence [A083577](https://oeis.org/A083577 "oeis:A083577") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")) are 13, 37, 73, 181, 337, 433, 541, 661, 937.

A **superstar prime** is a star prime whose prime index is also a star number. The first two such numbers are 661 and 1750255921.

A **reverse superstar prime** is a star number whose index is a star prime. The first few such numbers are 937, 7993, 31537, 195481, 679393, 1122337, 1752841, 2617561, 5262193.

The term "star number" or "stellate number" is occasionally used to refer to [octagonal numbers](https://en.wikipedia.org/wiki/Octagonal_number "Octagonal number").[[1]](https://en.wikipedia.org/wiki/Star_number#cite_note-1)

A **hexagonal number** is a [figurate number](https://en.wikipedia.org/wiki/Figurate_number "Figurate number"). The _n_th hexagonal number _h__n_ is the number of _distinct_ dots in a pattern of dots consisting of the _outlines_ of regular hexagons with sides up to n dots, when the hexagons are overlaid so that they share one [vertex](https://en.wikipedia.org/wiki/Vertex_\(geometry\) "Vertex (geometry)").

[![The first four hexagonal numbers.](https://upload.wikimedia.org/wikipedia/commons/thumb/f/f0/Hexagonal_numbers.svg/960px-Hexagonal_numbers.svg.png)](https://en.wikipedia.org/wiki/File:Hexagonal_numbers.svg "The first four hexagonal numbers.")

The formula for the _n_th hexagonal number

hn=2n2−n=n(2n−1)=2n(2n−1)2.![{\displaystyle h_{n}=2n^{2}-n=n(2n-1)={\frac {2n(2n-1)}{2}}.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/6a5c8027eb031f90a83fbb610c9419ce69739730)

The first few hexagonal numbers (sequence [A000384](https://oeis.org/A000384 "oeis:A000384") in the [OEIS](https://en.wikipedia.org/wiki/On-Line_Encyclopedia_of_Integer_Sequences "On-Line Encyclopedia of Integer Sequences")) are:

[1](https://en.wikipedia.org/wiki/1_\(number\) "1 (number)"), [6](https://en.wikipedia.org/wiki/6_\(number\) "6 (number)"), [15](https://en.wikipedia.org/wiki/15_\(number\) "15 (number)"), [28](https://en.wikipedia.org/wiki/28_\(number\) "28 (number)"), [45](https://en.wikipedia.org/wiki/45_\(number\) "45 (number)"), [66](https://en.wikipedia.org/wiki/66_\(number\) "66 (number)"), [91](https://en.wikipedia.org/wiki/91_\(number\) "91 (number)"), [120](https://en.wikipedia.org/wiki/120_\(number\) "120 (number)"), [153](https://en.wikipedia.org/wiki/153_\(number\) "153 (number)"), [190](https://en.wikipedia.org/wiki/190_\(number\) "190 (number)"), [231](https://en.wikipedia.org/wiki/231_\(number\) "231 (number)"), [276](https://en.wikipedia.org/wiki/276_\(number\) "276 (number)"), [325](https://en.wikipedia.org/wiki/325_\(number\) "325 (number)"), 378, 435, [496](https://en.wikipedia.org/wiki/496_\(number\) "496 (number)"), [561](https://en.wikipedia.org/wiki/561_\(number\) "561 (number)"), 630, 703, 780, 861, 946...

Every hexagonal number is a [triangular number](https://en.wikipedia.org/wiki/Triangular_number "Triangular number"), but only every _other_ triangular number (the 1st, 3rd, 5th, 7th, etc.) is a hexagonal number. Like a triangular number, the [digital root](https://en.wikipedia.org/wiki/Digital_root "Digital root") in base 10 of a hexagonal number can only be 1, 3, 6, or 9. The digital root pattern, repeating every nine terms, is "1 6 6 1 9 3 1 3 9".

Every even [perfect number](https://en.wikipedia.org/wiki/Perfect_number "Perfect number") is hexagonal, given by the formula

Mp2p−1=MpMp+12=h(Mp+1)/2=h2p−1![{\displaystyle M_{p}2^{p-1}=M_{p}{\frac {M_{p}+1}{2}}=h_{(M_{p}+1)/2}=h_{2^{p-1}}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/7ec42e137245e58a17dbe9029508c3998c0b1d6c)

where _M__p_ is a [Mersenne prime](https://en.wikipedia.org/wiki/Mersenne_prime "Mersenne prime"). No odd perfect numbers are known, hence all known perfect numbers are hexagonal.

For example, the 2nd hexagonal number is 2×3 = 6; the 4th is 4×7 = 28; the 16th is 16×31 = 496; and the 64th is 64×127 = 8128.

The largest number that cannot be written as a sum of at most four hexagonal numbers is [130](https://en.wikipedia.org/wiki/130_\(number\) "130 (number)"). [Adrien-Marie Legendre](https://en.wikipedia.org/wiki/Adrien-Marie_Legendre "Adrien-Marie Legendre") proved in 1830 that any [integer](https://en.wikipedia.org/wiki/Integer "Integer") greater than 1791 can be expressed in this way.

In addition, only two integers cannot be expressed using five hexagonal numbers (but can be with six), those being 11 and 26.

Hexagonal numbers should not be confused with [centered hexagonal numbers](https://en.wikipedia.org/wiki/Centered_hexagonal_number "Centered hexagonal number"), which model the standard packaging of [Vienna sausages](https://en.wikipedia.org/wiki/Vienna_sausage "Vienna sausage"). To avoid ambiguity, hexagonal numbers are sometimes called "cornered hexagonal numbers".

## Test for hexagonal numbers

One can efficiently test whether a positive integer _x_ is a hexagonal number by computing

n=8x+1+14.![{\displaystyle n={\frac {{\sqrt {8x+1}}+1}{4}}.}](https://wikimedia.org/api/rest_v1/media/math/render/svg/3fa4fd6ff400829790d842b2f8ee08394a8d80d0)

If _n_ is an integer, then _x_ is the _n_th hexagonal number. If _n_ is not an integer, then _x_ is not hexagonal.

The **polyhedral model** (also called the **polytope method**) is a mathematical framework for programs that perform large numbers of operations -- too large to be explicitly enumerated -- thereby requiring a _compact_ representation. Nested loop programs are the typical, but not the only example, and the most common use of the model is for [loop nest optimization](https://en.wikipedia.org/wiki/Loop_nest_optimization "Loop nest optimization") in [program optimization](https://en.wikipedia.org/wiki/Program_optimization "Program optimization"). The polyhedral method treats each loop iteration within nested loops as [lattice points](https://en.wikipedia.org/wiki/Lattice_points "Lattice points") inside mathematical objects called [polyhedra](https://en.wikipedia.org/wiki/Polytope "Polytope"), performs [affine transformations](https://en.wikipedia.org/wiki/Affine_transformation "Affine transformation") or more general non-affine transformations such as [tiling](https://en.wikipedia.org/wiki/Loop_tiling "Loop tiling") on the polytopes, and then converts the transformed polytopes into equivalent, but optimized (depending on targeted optimization goal), loop nests through polyhedra scanning.

## Simple example

Consider the following example written in [C](https://en.wikipedia.org/wiki/C_\(programming_language\) "C (programming language)"):

const int n = 100;
int i, j;
int a[n][n] = {{0,1}};

for (i = 1; i < n; i++) {
  for (j = 1; j < (i + 2) && j < n; j++) {
    a[i][j] = a[i - 1][j] + a[i][j - 1];
  }
}

for (i = 0; i < n; i++) {
  for (j = 0; j < n; ++j) {
    printf("%4d ", a[i][j]);
  }
  puts("");
}

The essential problem with this code is that each iteration of the inner loop on `a[i][j]` requires that the previous iteration's result, `a[i][j - 1]`, be available already. Therefore, this code cannot be parallelized or [pipelined](https://en.wikipedia.org/wiki/Pipeline_\(computing\) "Pipeline (computing)") as it is currently written.

An application of the polytope model, with the affine transformation (i′,j′)=(i+j,j)![{\displaystyle (i',\,j')=(i+j,\,j)}](https://wikimedia.org/api/rest_v1/media/math/render/svg/f4b6a0c677875545644ce7d35d44846c9c3d9cdd) and the appropriate change in the boundaries, will transform the nested loops above into:

a[i - j][j] = a[i - j - 1][j] + a[i - j][j - 1];

In this case, no iteration of the inner loop depends on the previous iteration's results; the entire inner loop can be executed in parallel. Indeed, given `a(i, j) = a[i-j][j]` then `a(i, j)` only depends on `a(i - 1, x)`, with x∈{j−1,j}![{\displaystyle x\in \{j-1,\,j\}}](https://wikimedia.org/api/rest_v1/media/math/render/svg/fa9dc150cd2f5b81fdc17a68e9126d2480f96d72). (However, each iteration of the outer loop does depend on previous iterations.)

In [computer science](https://en.wikipedia.org/wiki/Computer_science) and particularly in [compiler](https://en.wikipedia.org/wiki/Compiler "Compiler") design, **loop nest optimization** (LNO) is an optimization technique that applies a set of [loop transformations](https://en.wikipedia.org/wiki/Loop_transformation "Loop transformation") for the purpose of [locality](https://en.wikipedia.org/wiki/Locality_of_reference "Locality of reference") optimization or parallelization or another loop overhead reduction of the loop nests. ([Nested loops](https://en.wikipedia.org/wiki/Nested_loop "Nested loop") occur when one loop is inside of another loop.) One classical usage is to reduce memory access latency or the cache bandwidth necessary due to cache reuse for some common [linear algebra](https://en.wikipedia.org/wiki/Linear_algebra "Linear algebra") [algorithms](https://en.wikipedia.org/wiki/Algorithm "Algorithm").

The technique used to produce this optimization is called **loop tiling**,[[1]](https://en.wikipedia.org/wiki/Loop_nest_optimization#cite_note-MuchnickAssociates1997-1) also known as **loop blocking**[[2]](https://en.wikipedia.org/wiki/Loop_nest_optimization#cite_note-CardosoDiniz2011-2) or **strip mine and interchange**.

## Overview

Loop tiling partitions a loop's iteration space into smaller chunks or blocks, so as to help ensure data used in a loop stays in the [cache](https://en.wikipedia.org/wiki/CPU_Cache "CPU Cache") until it is reused. The partitioning of loop iteration space leads to partitioning of a large array into smaller blocks, thus fitting accessed array elements into cache size, enhancing cache reuse and eliminating cache size requirements.

An ordinary loop

for (i=0; i<N; ++i) {
  ...
}

can be blocked with a block size B by replacing it with

for (j=0; j<N; j+=B) {
  for (i=j; i<min(N, j+B); ++i) {
    ....
  }
}

where `min()` is a function returning the minimum of its arguments.

## Example: matrix-vector multiplication

The following is an example of matrix-vector multiplication. There are three arrays, each with 100 elements. The code does not partition the arrays into smaller sizes.

  int i, j, a[100][100], b[100], c[100];
  int n = 100;
  for (i = 0; i < n; i++) {
    c[i] = 0;
    for (j = 0; j < n; j++) {
      c[i] = c[i] + a[i][j] * b[j];
    }
  }

After loop tiling is applied using 2 * 2 blocks, the code looks like:

  int i, j, x, y, a[100][100], b[100], c[100];
  int n = 100;
  for (i = 0; i < n; i += 2) {
    c[i] = 0;
    c[i + 1] = 0;
    for (j = 0; j < n; j += 2) {
      for (x = i; x < min(i + 2, n); x++) {
        for (y = j; y < min(j + 2, n); y++) {
          c[x] = c[x] + a[x][y] * b[y];
        }
      }
    }
  }

The original loop iteration space is _n_ by _n_. The accessed chunk of array a[i, j] is also _n_ by _n_. When _n_ is too large and the cache size of the machine is too small, the accessed array elements in one loop iteration (for example, `i = 1`, `j = 1 to n`) may cross cache lines, causing cache misses.

## Tiling size

It is not always easy to decide what value of tiling size is optimal for one loop because it demands an accurate estimate of accessed array regions in the loop and the cache size of the target machine. The order of loop nests ([loop interchange](https://en.wikipedia.org/wiki/Loop_interchange "Loop interchange")) also plays an important role in achieving better cache performance. Explicit blocking requires choosing a tile size based on these factors. By contrast, [cache-oblivious algorithms](https://en.wikipedia.org/wiki/Cache-oblivious_algorithm "Cache-oblivious algorithm") are designed to make efficient use of cache without explicit blocking.

## Example: matrix multiplication

Many large mathematical operations on computers end up spending much of their time doing [matrix multiplication](https://en.wikipedia.org/wiki/Matrix_multiplication "Matrix multiplication"). The operation is:

C = A×B

where A, B, and C are N×N arrays. Subscripts, for the following description, are in form `C[row][column]`.

The basic loop is:

int i, j, k;

for (i = 0; i < N; ++i)
{
    for (j = 0; j < N; ++j)
    {
        C[i][j] = 0;

        for (k = 0; k < N; ++k)
            C[i][j] += A[i][k] * B[k][j];
    }
}

There are three problems to solve:

- Floating point additions take some number of cycles to complete. In order to keep an [adder](https://en.wikipedia.org/wiki/Adder_\(electronics\) "Adder (electronics)") with multiple cycle latency busy, the code must update multiple [accumulators](https://en.wikipedia.org/wiki/Accumulator_\(computing\) "Accumulator (computing)") in parallel.
- Machines can typically do just one memory operation per [multiply-add](https://en.wikipedia.org/wiki/Multiply%E2%80%93add "Multiply–add"), so values loaded must be reused at least twice.
- Typical PC memory systems can only sustain one 8-byte doubleword per 10–30 double-precision multiply–adds, so values loaded into the cache must be reused many times.

The original loop calculates the result for one entry in the result matrix at a time. By calculating a small block of entries simultaneously, the following loop reuses each loaded value twice, so that the inner loop has four loads and four multiply–adds, thus solving problem #2. By carrying four accumulators simultaneously, this code can keep a single floating point adder with a latency of 4 busy nearly all the time (problem #1). However, the code does not address the third problem. (Nor does it address the cleanup work necessary when N is odd. Such details will be left out of the following discussion.)

for (i = 0; i < N; i += 2)
{
    for (j = 0; j < N; j += 2)
    {
        acc00 = acc01 = acc10 = acc11 = 0;
        for (k = 0; k < N; k++)
        {
            acc00 += B[k][j + 0] * A[i + 0][k];
            acc01 += B[k][j + 1] * A[i + 0][k];
            acc10 += B[k][j + 0] * A[i + 1][k];
            acc11 += B[k][j + 1] * A[i + 1][k];
        }
        C[i + 0][j + 0] = acc00;
        C[i + 0][j + 1] = acc01;
        C[i + 1][j + 0] = acc10;
        C[i + 1][j + 1] = acc11;
    }
}

This code has had both the `i` and `j` iterations blocked by a factor of two and had both the resulting two-iteration inner loops completely unrolled.

This code would run quite acceptably on a Cray Y-MP (built in the early 1980s), which can sustain 0.8 multiply–adds per memory operation to main memory. A machine like a 2.8 GHz Pentium 4, built in 2003, has slightly less memory bandwidth and vastly better floating point, so that it can sustain 16.5 multiply–adds per memory operation. As a result, the code above will run slower on the 2.8 GHz Pentium 4 than on the 166 MHz Y-MP!

A machine with a longer floating-point add latency or with multiple adders would require more accumulators to run in parallel. It is easy to change the loop above to compute a 3x3 block instead of a 2x2 block, but the resulting code is not always faster. The loop requires registers to hold both the accumulators and the loaded and reused A and B values. A 2x2 block requires 7 registers. A 3x3 block requires 13, which will not work on a machine with just 8 floating point registers in the [ISA](https://en.wikipedia.org/wiki/Instruction_set "Instruction set"). If the CPU does not have enough registers, the compiler will schedule extra loads and stores to spill the registers into stack slots, which will make the loop run slower than a smaller blocked loop.

Matrix multiplication is like many other codes in that it can be limited by memory bandwidth, and that more registers can help the compiler and programmer reduce the need for memory bandwidth. This _[register pressure](https://en.wikipedia.org/wiki/Register_pressure "Register pressure")_ is why vendors of [RISC](https://en.wikipedia.org/wiki/RISC "RISC") CPUs, who intended to build machines more parallel than the general purpose [x86](https://en.wikipedia.org/wiki/X86 "X86") and [68000](https://en.wikipedia.org/wiki/68000 "68000") CPUs, adopted 32-entry floating-point [register files](https://en.wikipedia.org/wiki/Register_file "Register file").

The code above does not use the cache very well. During the calculation of a horizontal stripe of C results, one horizontal stripe of A is loaded, and the entire matrix B is loaded. For the entire calculation, C is stored once (that's good), A is loaded into the cache once (assuming a stripe of A fits in the cache with a stripe of B), but B is loaded N/ib times, where ib is the size of the strip in the C matrix, for a total of N3/ib doubleword loads from main memory. In the code above, _ib_ is 2.

The next step to reduce the memory traffic is to make ib as large as possible. It needs to be larger than the "balance" number reported by streams. In the case of one particular 2.8 GHz Pentium 4 system used for this example, the balance number is 16.5. The second code example above cannot be extended directly, since that would require many more accumulator registers. Instead, the loop is _blocked_ over i. (Technically, this is actually the second time i is blocked, as the first time was the factor of 2.)

for (ii = 0; ii < N; ii += ib)
{
    for (j = 0; j < N; j += 2)
    {
        for (i = ii; i < ii + ib; i += 2)
        {
            acc00 = acc01 = acc10 = acc11 = 0;
            for (k = 0; k < N; k++)
            {
                acc00 += B[k][j + 0] * A[i + 0][k];
                acc01 += B[k][j + 1] * A[i + 0][k];
                acc10 += B[k][j + 0] * A[i + 1][k];
                acc11 += B[k][j + 1] * A[i + 1][k];
            }
            C[i + 0][j + 0] = acc00;
            C[i + 0][j + 1] = acc01;
            C[i + 1][j + 0] = acc10;
            C[i + 1][j + 1] = acc11;
        }
    }
}

With this code, ib can be set to any desired parameter, and the number of loads of the B matrix will be reduced by that factor. This freedom has a cost: N×ib slices of the A matrix are being kept in the cache. As long as that fits, this code will not be limited by the memory system.

So what size matrix fits? The example system, a 2.8 GHz Pentium 4, has a 16KB primary data cache. With ib=20, the slice of the A matrix in this code will be larger than the primary cache when N > 100. For problems larger than that, another trick is needed.

That trick is reducing the size of the stripe of the B matrix by blocking the k loop so that the stripe is of size ib × kb. Blocking the k loop means that the C array will be loaded and stored N/kb times, for a total of ⁠2∗N3/kb![{\displaystyle 2*N^{3}/kb}](https://wikimedia.org/api/rest_v1/media/math/render/svg/c022d7699cf236f5e76ee8c55645eff51326018e)⁠ memory transfers. B is still transferred N/ib times, for ⁠N3/ib![{\displaystyle N^{3}/ib}](https://wikimedia.org/api/rest_v1/media/math/render/svg/011a06762642b14ef43d9b15e506b32b100bf435)⁠ transfers. So long as

2*N/kb + N/ib < N/balance

the machine's memory system will keep up with the floating point unit and the code will run at maximum performance. The 16KB cache of the Pentium 4 is not quite big enough: if ib=24 and kb=64 were chosen instead, 12KB of the cache would be used—avoiding completely filling it, which is desirable so the C and B arrays have to have some room to flow through. These numbers come within 20% of the peak floating-point speed of the processor.

Here is the code with loop `k` blocked.

for (ii = 0; ii < N; ii += ib)
{
    for (kk = 0; kk < N; kk += kb)
    {
        for (j=0; j < N; j += 2)
        {
            for (i = ii; i < ii + ib; i += 2)
            {
                if (kk == 0)
                    acc00 = acc01 = acc10 = acc11 = 0;
                else
                {
                    acc00 = C[i + 0][j + 0];
                    acc01 = C[i + 0][j + 1];
                    acc10 = C[i + 1][j + 0];
                    acc11 = C[i + 1][j + 1];
                }
                for (k = kk; k < kk + kb; k++)
                {
                    acc00 += B[k][j + 0] * A[i + 0][k];
	                acc01 += B[k][j + 1] * A[i + 0][k];
	                acc10 += B[k][j + 0] * A[i + 1][k];
	                acc11 += B[k][j + 1] * A[i + 1][k];
                }
                C[i + 0][j + 0] = acc00;
                C[i + 0][j + 1] = acc01;
                C[i + 1][j + 0] = acc10;
                C[i + 1][j + 1] = acc11;
            }
        }
    }
}

The above code examples do not show the details of dealing with values of N which are not multiples of the blocking factors. Compilers which do loop nest optimization emit code to clean up the edges of the computation. For example, most LNO compilers would probably [split](https://en.wikipedia.org/wiki/Loop_splitting "Loop splitting") the kk == 0 iteration off from the rest of the `kk` iterations, to remove the if statement from the `i` loop. This is one of the values of such a compiler: while it is straightforward to code the simple cases of this optimization, keeping all the details correct as the code is replicated and transformed is an error-prone process.

The above loop will only achieve 80% of peak flops on the example system when blocked for the 16KB L1 cache size. It will do worse on systems with even more unbalanced memory systems. Fortunately, the Pentium 4 has 256KB (or more, depending on the model) high-bandwidth level-2 cache as well as the level-1 cache. There is a choice:

- Adjust the block sizes for the level-2 cache. This will stress the processor's ability to keep many instructions in flight simultaneously, and there is a good chance it will be unable to achieve full bandwidth from the level-2 cache.
- Block the loops again, again for the level-2 cache sizes. With a total of three levels of blocking (for the register file, for the L1 cache, and the L2 cache), the code will minimize the required bandwidth at each level of the [memory hierarchy](https://en.wikipedia.org/wiki/Memory_hierarchy "Memory hierarchy"). Unfortunately, the extra levels of blocking will incur still more loop overhead, which for some problem sizes on some hardware may be more time-consuming than any shortcomings in the hardware's ability to stream data from the L2 cache.

Rather than specifically tune for one particular cache size, as in the first example, a [cache-oblivious algorithm](https://en.wikipedia.org/wiki/Cache-oblivious_algorithm "Cache-oblivious algorithm") is designed to take advantage of any available cache, no matter what its size is. This automatically takes advantage of two or more levels of memory hierarchy, if available. Cache-oblivious algorithms for [matrix multiplication](https://en.wikipedia.org/wiki/Cache-oblivious_matrix_multiplication "Cache-oblivious matrix multiplication") are known.
