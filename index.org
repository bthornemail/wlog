** Authority Control

*** Canonical Names

- WOLOG :: canonical project/theory/documentation name
- WLOG :: engineering alias / shorthand only
- Omicron :: timing / ISA / periodic alignment thread
- Polyform :: structural arrangement of lawful cells; can act as data, program object, packet, or witness depending on layer
- Polynomial :: symbolic law over values, coordinates, or forms
- Predicate :: recognizer or constraint over forms, laws, or values
- Program :: executable replay over forms/laws/predicates
- PG :: property-graph surface
- Aztec embedding :: bitwise replay carrier, not source of truth
- semantic web :: RDF / Turtle / SHACL / URI integration layer
- language tag :: BCP 47 identifier treated as a pure type contract boundary
- WOLOG language :: direct surface language lowered into a CPS core IR
- virtual codepoint :: dual-address 40-bit identity plus symbolic alias for basis-cell algebra
- scene :: deterministic reduced world view from runtime events
- frame :: frozen capture artifact derived from world/scene state
- viewport :: local ephemeral viewing state
- composer :: authoring / overlay / patch surface

*** Alias Policy

- record aliases explicitly when they are useful
- prefer one canonical spelling in docs and code comments
- keep legacy names searchable, but mark them as aliases

Examples:

- =WLOG= -> alias of =WOLOG=
- =Aztec= -> short for =Aztec embedding= only when context is already binary/replay
- =viewer shell= -> page-level projection, not core viewer law

* Catalog Geometry

This section defines how geometric or encoded address spaces relate to
cataloging. The main rule is:

- authority is canonical
- mapping is federated
- projection is downstream

Do not let a display or transport encoding become the source of truth.

** Three Semantic Spaces

*** Local Space

Purpose:
- local aliases
- local glyphs
- local dialects
- local community vocabularies
- private or node-specific agreement

Examples:
- local PUA assignments
- community shorthand
- temporary experimental names

Status:
- useful
- non-canonical
- may differ across nodes

*** Federated Space

Purpose:
- shared mappings between local systems
- advisory equivalence
- translation and alignment tables
- inter-node agreement

Examples:
- word-to-synset mappings
- federation-specific correspondence tables
- negotiated naming bridges

Status:
- shared
- advisory unless promoted
- stable enough for exchange, but not final truth

*** Canonical Space

Purpose:
- authority-controlled identity
- stable concept records
- semantic contracts
- SHACL/Core validation boundaries
- repo-level and network-level durable meaning

Examples:
- =urn:wolog:synset:100001=
- =urn:wolog:module:scene=
- =urn:wolog:artifact:frame:abc123=

Status:
- canonical
- encoding-agnostic
- durable

** Authority, Mapping, Projection

*** Authority Record

An authority record defines the canonical identity of a thing.

Examples:
- concept
- file/module
- graph node
- language tag contract
- frame artifact

Fields usually include:
- canonical ID
- canonical name
- aliases
- type
- status
- relations

*** Mapping Record

A mapping record relates one local or federated identity to another.

Examples:
- local term -> canonical synset
- old module name -> current canonical module name
- community glyph -> canonical concept

Mapping records are not the same thing as authority records.

*** Projection Record

A projection record describes how a canonical or federated object appears on a
particular surface.

Examples:
- Turtle serialization
- SHACL shape
- PG node/edge rendering
- SVG projection
- UTF-8/UTF-16 encoding
- PUA or surrogate-pair display surface

Projection is always downstream of authority.

** Unicode Projection Rules

Unicode may be used as:
- a text surface
- a framing surface
- a local glyph space
- an optional transport/view encoding

Unicode should not be used as:
- the sole canonical semantic identifier layer
- the primary authority record layer

*** Private Use Areas

PUA and supplementary private use planes are acceptable as:
- local language picking space
- node-local glyph registry
- community-specific symbol overlays

They are not by themselves canonical semantic truth.

*** Surrogate Pairs

Surrogate-pair thinking is useful as a projection model for:
- channel
- wave
- event
- variation

But surrogate pairs should not be treated as the canonical semantic atoms.

Reason:
- surrogates are UTF-16 machinery
- they are encoding-dependent
- they are awkward as durable RDF/URI/catalog identifiers

Use them as projection or transport only.

** Recommended Identifier Order

Use this order of precedence:

#+begin_example
canonical semantic ID
-> authority record
-> federated mapping
-> local alias/glyph
-> Unicode / UI / transport projection
#+end_example

Examples:

- canonical :: =urn:wolog:synset:100001=
- federated :: =urn:wolog:federation:alpha:mapping:wisdom=
- local :: =U+E123=
- projection :: UTF-16 pair or visible glyph form

** Catalog Use of Channel / Wave / Event Thinking

The channel/wave/event model is still valuable for cataloging, but as structured
classification metadata rather than canonical identity.

Useful roles:
- channel :: broad class or carrier axis
- wave :: operational or semantic band
- event :: specific action/transition kind
- variation :: local refinement

This can be represented as fields on records, bitfields in binary carriers, or
classification tags in the catalog.

** Observer Rule

The observer/interpreter remains outside the encoded object.

Meaning is reconstructed by:
- authority records
- mapping records
- projection rules
- interpreter context

This is important:
- the observer is not stored inside the encoding as the final truth
- the observer verifies, aligns, and interprets

** Catalog Design Rule

For WOLOG:

- geometry can inform classification
- transport can inform framing
- Unicode can inform projection
- but authority must remain upstream

Short form:

#+begin_example
authority -> mapping -> projection
not
projection -> authority
#+end_example
